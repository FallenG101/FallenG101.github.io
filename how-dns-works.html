How DNS Works

When a device needs an address for a domain, it asks a recursive resolver. If the resolver has no valid cached answer, it follows referrals until it reaches an authoritative server.

A lookup in six steps

  1. The device asks. The browser or operating system sends a question to its configured resolver.
  2. The resolver checks its cache. A valid cached answer can be returned immediately.
  3. The root points to a TLD. For a name ending in .com, the root server refers the resolver to .com name servers.
  4. The TLD points to the domain. The .com servers identify the authoritative name servers for the domain.
  5. The authoritative server answers. It returns the requested record, such as an A or AAAA address record.
  6. The resolver replies and caches. The device receives the answer and can connect to the destination.

The hierarchy

Domain names are read from right to left. In www.example.com, .com is the top-level domain, example is the second-level domain, and www is a host name below it. The root sits above all top-level domains.

Why caching helps

Each record has a time to live (TTL). A resolver can reuse the answer until that time expires. A shorter TTL helps changes become visible sooner but can increase repeated queries; a longer TTL reduces repeated work but may keep older information in caches for longer.
