How DNS Works

When a device needs a website’s address, it asks a resolver. If the resolver has no saved answer, it asks other DNS servers until it finds the one with the answer.

A lookup in six steps

  1. The device asks. The browser or operating system sends a question to its resolver.
  2. The resolver checks its saved answers. If it has a current answer, it returns it.
  3. The root points to a top-level domain. For a name ending in .com, it points the resolver to .com name servers.
  4. The top-level domain points to the domain. The .com servers identify the name servers for the domain.
  5. The domain’s name server answers. It returns the requested record, such as an IPv4 or IPv6 address.
  6. The resolver replies. The device gets the answer and can connect to the website or service. The resolver saves the answer for a while.

The hierarchy

Domain names are read from right to left. In www.example.com, .com is the top-level domain, example is the name within it, and www is a host name. The root sits above all top-level domains.

Why caching helps

Each record has a time to live (TTL), or how long a resolver can reuse an answer. A short TTL helps changes show up sooner but causes more lookups. A long TTL means fewer lookups, but old answers may stick around longer.
