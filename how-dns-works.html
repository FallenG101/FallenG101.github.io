How DNS Works

When a device needs the address for a domain, it asks a recursive resolver. If the answer is not already saved, the resolver follows directions from other DNS servers until it reaches one that has the official record.

A lookup in six steps

  1. The device asks. The browser or operating system sends a question to its chosen resolver.
  2. The resolver checks its saved answers. If it has a current answer, it can return it right away.
  3. The root points to a top-level domain. For a name ending in .com, the root server points the resolver to .com name servers.
  4. The top-level domain points to the domain. The .com servers tell the resolver which name servers manage the domain.
  5. The domain’s name server answers. It returns the requested record, such as an IPv4 or IPv6 address.
  6. The resolver replies and saves the answer. The device receives it and can connect to the website or service.

The hierarchy

Domain names are read from right to left. In www.example.com, .com is the top-level domain, example is the second-level name, and www is a host name. The root is above all top-level domains.

Why caching helps

Each record has a time to live (TTL), which sets how long a resolver can reuse an answer. A shorter TTL helps updates appear sooner but means more lookups. A longer TTL reduces lookups but can keep old answers in use for longer.
